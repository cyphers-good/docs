# 문서 작성 스킬

이 저장소는 팀원이 필요한 정보를 빠르게 찾는 것을 목표로 하는 Fumadocs 문서 사이트입니다.
문서는 "읽는 사람이 지금 하려는 작업"을 중심으로 구성하고, 불필요한 배경 설명을 넣지 않습니다.

## 기본 규칙

- 문서는 `content/docs/*.mdx` 에 작성합니다. frontmatter에 `title`, `description`이 필수입니다.
- 새 문서를 추가하면 `content/docs/meta.json` 의 `pages` 배열에 파일 이름을 등록합니다.
- 모든 문장은 한국어로 쓰고, `.claude/output-styles/fluent-korean.md` 지침을 준수합니다.
- 사용자가 요청한 내용만 문서에 넣습니다. 요청받지 않은 섹션이나 페이지를 임의로 추가하지 않습니다.
- 작성 후에는 반드시 `npm run build` 로 빌드가 통과하는지 확인합니다.

## 구조 선택 기준

내용의 형태에 따라 다음 순서로 구조를 고릅니다.

| 내용 형태 | 사용할 구조 | 이유 |
| --- | --- | --- |
| 독자가 상황에 따라 다른 절차를 봐야 함 | `<Tabs>` / `<Tab>` | 자신에게 해당하는 절차만 보게 하여 혼란을 줄입니다 |
| 순서대로 따라하는 절차 | `<Steps>` / `<Step>` + 명령어 코드 블록 | 번호가 붙은 세로 단계로 진행 위치를 잃지 않게 합니다 |
| 항목별 역할·비교 정보 | 표 | 나열형 정보는 문장보다 표가 빠르게 읽힙니다 |
| **여러 주체(브랜치, 서비스 등)가 얽힌 복잡한 흐름** | **애니메이션 도식** | 아래 기준 참조 |

Tabs, Steps 컴포넌트는 `mdx-components.tsx` 에 이미 등록되어 있으므로 MDX에서 바로 사용할 수 있습니다.

## 복잡한 흐름에는 애니메이션 도식을 사용합니다

다음 조건 중 하나라도 해당하면, 정적인 텍스트 도식 대신 단계별 애니메이션 도식을 사용합니다.

- 여러 주체(브랜치, 서비스, 시스템)가 서로 상호작용하며 순서가 중요한 흐름
- 단계가 4개 이상이고, 각 단계에서 상태가 변하는 절차
- 화살표만으로 표현하면 한눈에 따라가기 어려운 분기·병합 구조

텍스트 한 줄로 충분한 단순 흐름(`A ──▶ B` 수준)에는 애니메이션을 쓰지 않습니다.
애니메이션 도식을 만들거나 수정하는 구체적인 방법은 `.claude/skills/animated-diagram/SKILL.md` 를 읽고 따릅니다.

## 작업 마무리

1. `npm run build` 통과를 확인합니다.
2. UI가 바뀌었다면 브라우저 스크린샷으로 렌더링을 확인합니다 (animated-diagram 스킬의 검증 절차 참조).
3. 커밋과 브랜치는 CLAUDE.md의 브랜치·커밋 규칙을 따릅니다.
